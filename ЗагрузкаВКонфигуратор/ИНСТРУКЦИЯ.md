# Обработка «Многофункциональная выгрузка из 1С УТ10 в БП3»

Имя обработки в метаданных: `ОбменУТ10БПv3`.  
Синоним на форме: **Многофункциональная выгрузка из 1С УТ10 в БП3**.

Эта инструкция для человека, который открывает форму первый раз. Цель — перенести **одну** реализацию из КА в БП и проверить, что в РТУ БП появились водитель, ТС, перевозчик, ЕГАИС и номер заказа.

Что лежит в этой папке:

| Файл | Зачем |
|------|--------|
| `МодульФормы.bsl` | модуль основной формы — его нужно загрузить в вашу обработку |
| `ПереносДанныхУТ10БП3OLEv231.xml` + папка рядом | полная выгрузка (нужна, только если собираете новый `.epf` из файлов) |

## 2. Загрузить модуль в конфигураторе (обязательно, первый шаг)

Делается в **конфигураторе базы БП**, на той обработке, которой вы уже пользуетесь.

1. Сделайте копию текущего `.epf` (на случай отката).
2. Конфигуратор БП → **Файл → Открыть** → ваш `.epf`.
3. В дереве обработки откройте **Формы → Форма**.
4. Откройте **модуль формы** (вкладка «Модуль» или правой кнопкой по форме → «Открыть модуль формы»).
5. **Текст → Загрузить из файла…** (или Ctrl+A, удалить, затем вставить).
6. Укажите файл:

   `ЗагрузкаВКонфигуратор\МодульФормы.bsl`

7. Проверьте, что в модуле есть процедура `ЗаполнитьТранспортИзРегистраКА` (поиск **Ctrl+F**). Если нет — загрузили не тот файл.
8. **Файл → Сохранить** (или «Сохранить как», если хотите новый `.epf`).
9. Закройте конфигуратор. Дальше работайте в **1С:Предприятии**.

Метаданные обработки (реквизиты, форма) не менялись — меняется только модуль формы.

### Если конфигуратор ругается на кодировку

Файл в UTF-8 с BOM. Если текст «кракозябрами»: в диалоге загрузки укажите кодировку **UTF-8**.

### Если обработка открывается через «Дополнительные отчеты и обработки»

1С запоминает старый модуль. После сохранения `.epf` зайдите в  
**Администрирование → Печатные формы, отчеты и обработки → Дополнительные отчеты и обработки**,  
откройте карточку этой обработки и **загрузите `.epf` заново**. Иначе будет старая версия без транспорта.

## 3. Подготовить одну реализацию в КА (до открытия обработки)

Выберите **одну** реализацию, у которой в КА на транспортной вкладке / ТТН реально заполнены:

- водитель
- автомобиль (госномер / марка)
- перевозчик (если не «едем сами»)
- по возможности номер фиксации ЕГАИС и номер заказа

Запишите на бумагу: **номер, дату, ФИО водителя, госномер, перевозчика, номер фиксации, номер заказа**.

Данные в КА лежат в регистре `alkТранспортнаяИнформация` по этой реализации, а не в шапке РТУ. Если в КА на ТТН всё видно — этого достаточно, регистр можно не открывать.

Документ в КА должен быть **проведён**. Непроведённые обработка не берёт (пока в настройках не включён отдельный флажок «Переносить непроведенные документы»).

---

## 4. Открыть обработку в 1С:Предприятии БП

Любой из способов:

**Способ А.** **Файл → Открыть** → тот `.epf`, который сохранили в п. 2.

**Способ Б.** Раздел **Дополнительные отчеты и обработки** (или Администрирование, см. выше) → ваша обработка → **Выполнить**.

Откроется форма. Сверху командная панель с кнопками:

- **Получить данные**
- **Предварительный просмотр**
- **Создать документы** (сразу после открытия серая — так и должно быть)

Внизу закладки. Сразу открыта закладка **Настройки**. Закладка **Предварительный просмотр** сначала скрыта.

---

## 5. Закладка «Настройки»: подключение к КА

Слева блок **Подключение**. Обработка работает **из БП** и подключается **к базе КА**.

Если поля уже заполнены с прошлого раза — **не трогайте**, переходите к п. 6.

Если пусто:

1. **Тип коннектора**
   - `ComConnector` — обычное COM-подключение (берите его).
   - `Application` — откроет отдельное окно 1С КА. Нужно редко.
2. **Тип соединения**
   - `Файл` — файловая база КА. Становится доступно поле **Путь**. Укажите каталог базы (там лежат `1Cv8.1CD` / папка информационной базы).
   - `Сервер` — клиент-серверная КА. Становятся доступны **Сервер** (имя кластера 1С) и **База УТ** (имя информационной базы на сервере).
3. **Версия платформы** — оставьте `Авто`.
4. **Пользователь** и **Пароль** — пользователь **базы КА** (не БП), у которого есть права на чтение документов.
5. Галка **Аутентификация ОС** — только если входите в КА учёткой Windows, без логина 1С.
6. Галки **Держать соединение открытым** / **Показывать сеанс** не нужны для разовой проверки.

Подключаться кнопкой отдельно не надо: соединение случится само при **Получить данные**.

---

## 6. Период и организация

Вверху слева группа **Период и организации выгрузки**:

1. **Период с** — дата вашей реализации (можно тот же день).
2. **по** — та же дата (или конец дня/недели, если не помните точно).
3. **Организации** — организация **из БП**, та же фирма, что в КА.

Организацию указать **обязательно**. Обработка ищет документы в КА по **ИНН** выбранных организаций. Если список пустой — реализаций не найдёт.

Период тоже обязателен. Без него будет сообщение: `Период должен быть заполнен`.

Для проверки одной РТУ ставьте **один день**.

---

## 7. Что включить в «Выгружаемые документы»

Справа таблица **Выгружаемые документы**. Это список видов документов. Галка в строке = этот вид будет переноситься.

Нужна только реализация:

1. Над таблицей две кнопки без подписи: **установить все флаги** и **снять все флаги**. Нажмите **снять все** (чтобы случайно не уехали касса, банк, поступления).
2. Найдите строку **Реализации** и поставьте галку.
3. Остальное не включайте.  
   **Сч. ф. выданные** — только если отдельно хотите ещё счёт-фактуру. Для проверки транспорта не нужно.

Если ничего не отмечено, при получении данных будет:  
`В списке объектов для переноса ничего не выбрано!`

---

## 8. Что включить в «Настройки переноса»

Слева ниже подключения таблица **Настройки переноса** (это список галок, не путать с выгружаемыми документами).

Для проверки транспорта на уже существующей РТУ БП поставьте:

| Строка в списке | Ставить? | Зачем |
|-----------------|----------|--------|
| **Перезаписывать выгруженные документы** | **да** | без неё обработка **пропустит** РТУ, которая уже есть в БП |
| **Проводить документы** | по желанию | провести РТУ после записи |
| **Отменять проведение перезаписываемого документа** | **да, если РТУ в БП уже проведена** | иначе запись в проведённый документ может не пройти |

**Не ставьте:**

- **Перезаписывать только документы с изменёнными суммами** — сумма не менялась, обработка снова пропустит документ, и транспорт не приедет.

Остальные галки этого списка для разовой проверки не трогайте.

---

## 9. Кнопка «Получить данные»

1. Нажмите **Получить данные** (первая кнопка сверху).
2. Если таблицы уже заполнялись раньше, спросит:  
   `Данные в таблицах будут перезаполнены, продолжить?` → **Да**.
3. Внизу бежит «Соединение» / «Получение данных». Форма переключится на закладку **Контрагенты**.

Если не подключилось к КА:

- сообщение `Не удалось подключиться к БД`;
- проверьте путь/сервер/базу, пользователя КА, что база КА не открыта монопольно в конфигураторе.

Когда данные получены, кнопки **Предварительный просмотр** и **Создать документы** должны стать **активными**.

Если они так и серые:

- на закладке **Контрагенты** красные строки (контрагент/договор не найдены) — подберите контрагента в колонке или нажмите **Создать контрагентов** / **Создать договоры**;
- то же для закладок **Номенклатура** / **Склады**, если они видны.

Для одной уже переносившейся реализации контрагенты обычно уже есть, кнопки сразу становятся активными.

---

## 10. Кнопка «Предварительный просмотр»

1. Нажмите **Предварительный просмотр**.
2. Откроется закладка **Предварительный просмотр** с таблицей документов из КА за период.

Колонки: галка **Загружать**, **Тип**, **Номер**, **Дата**, **Контрагент**, **Договор**, **Организация**, **Сумма**, **Склад**, **Статус**.

3. Найдите вашу реализацию по номеру и дате с бумажки.
4. Чтобы не создать лишнего:
   - на панели таблицы нажмите **снять все** (кнопка без подписи, команда «Снять все»);
   - поставьте галку **Загружать** только на одной нужной строке.

Если списка нет — период, организация или галка «Реализации» заданы не так. Вернитесь на **Настройки** и повторите **Получить данные**.

---

## 11. Кнопка «Создать документы»

1. Не снимайте галку **Реализации** в списке объектов.
2. Нажмите **Создать документы**.
3. В окне сообщений 1С должно появиться что-то вроде:
   - `Создан и записан документ …` — РТУ в БП не было, создали новую;
   - `Перезаполнен и записан документ …` — нашли старую РТУ и перезаписали, включая транспорт.

Если сообщений про вашу РТУ нет и в предпросмотре строка с ошибкой — чаще всего **не включена перезапись** (п. 8). Включите и повторите с п. 9.

Кнопка **Перейти в документ** на закладке предпросмотра открывает созданную РТУ в БП.

---

## 12. Что сверить в РТУ БП

Откройте созданную/обновлённую **Реализацию товаров и услуг** в БП  
(раздел **Продажи → Реализация (акты, накладные)**, поиск по номеру).

Поля доставки / транспорта (то, что уходит в Титул 1 Контура):

| Поле в форме РТУ БП | Откуда должно взяться |
|---------------------|------------------------|
| **Водитель** | ФИО из регистра КА |
| **Водительское удостоверение** | номер ВУ физлица-водителя в КА |
| **Марка автомобиля** | справочник ТС КА (`уатТС`) |
| **Регистрационный знак автомобиля** | госномер того же ТС |
| **Марка прицепа** / **Регистрационный знак прицепа** | прицеп из регистра |
| **Перевозчик** | контрагент БП по ИНН/наименованию (пусто, если в КА «заказчик сам») |
| **Адрес доставки** | адрес из регистра |
| **Перевозка автотранспортом** | галка, если есть водитель или госномер |
| **Сопроводительные документы** | текст `Фиксация ЕГАИС № …` |
| таблица **Товары** → **Номер заказа** | `alkНомерЗаказа` / `алкНомерЗаказа` шапки КА |

Сверьте с бумажкой из КА. Если совпало — обработка делает своё, дальше Контур.

---

## 13. Проверка Контур.Логистика, Титул 1

Контур читает **РТУ БП**, не ТТН КА.

1. В БП из этой реализации создайте ЭТрН / ЭЗЗ, как обычно.
2. В **Титуле 1** должны быть водитель, ТС, перевозчик, адрес.

Если в РТУ поля есть, а в Титуле 1 пусто — это настройка соответствия Контура, не перенос.

---

## 14. Если что-то пустое

1. **Водитель / ТС пустые в БП**  
   В КА откройте регистр сведений **Транспортная информация (КТ-2000)** (`alkТранспортнаяИнформация`) и найдите запись с объектом = эта РТУ. Нет записи — переносить нечего.

2. **Госномер пустой, марка есть (или наоборот)**  
   У справочника `уатТС` в этой базе другие имена реквизитов. Пришлите карточку `уатТС` (имена полей) — допишем чтение.

3. **Перевозчик пустой**  
   В КА стоит «заказчик сам», либо в БП нет контрагента с тем же ИНН/наименованием.

4. **Документ в БП не изменился**  
   Не включили **Перезаписывать выгруженные документы**, либо включили «только с изменёнными суммами». Исправьте п. 8 и повторите.

5. **В модуле нет `ЗаполнитьТранспортИзРегистраКА`**  
   В Предприятии открыт старый `.epf`. Откройте тот, который сохранили после загрузки модуля. Если обработка из «дополнительных» — загрузите `.epf` в карточку заново.

6. **Форма не открывается, ошибка компиляции / `Возврат` вне процедуры**  
   В модуле был лишний хвост в конце. В актуальном `МодульФормы.bsl` его нет: последняя строка файла — `КонецФункции`. Загрузите модуль ещё раз из этой папки.

## 15. Собрать новый `.epf` из XML (необязательно)

Если удобнее получить готовый `.epf` из этой выгрузки, в конфигураторе пакетный режим:

```
1cv8.exe DESIGNER /DisableStartupDialogs /F "C:\ПутьКБазеБП" /N "Админ" /P "пароль" /LoadExternalDataProcessorOrReportFromFiles "C:\...\ЗагрузкаВКонфигуратор\ПереносДанныхУТ10БП3OLEv231.xml" "C:\...\ОбменУТ10БПv3.epf"
```

Первый путь — корневой xml из этой папки. Второй — куда положить готовый `.epf`.

Потом в Предприятии: **Файл → Открыть** → этот `.epf`.
